# Trade CSV Column Specification & Accounting Standards

This document defines the schema, units, accounting definitions, and reconciliation identities for exported trade CSVs generated by the Deskmind research and backtest engines (`reports/research/trades_<hypothesis>.csv`).

---

## 1. Accounting Invariants & Principles

### A. Fill Prices Already Include Slippage
- The `entry_price` and `exit_price` recorded in the engine are the **actual executed fill prices** after applying market/stop slippage.
- For a Long trade:
  $$\text{gross\_pnl\_usd} = (\text{exit\_price} - \text{entry\_price}) \times \text{qty}$$
- For a Short trade:
  $$\text{gross\_pnl\_usd} = (\text{entry\_price} - \text{exit\_price}) \times \text{qty}$$
- Because fill prices directly reflect executed execution prices, `gross_pnl_usd` **already includes slippage**.

### B. Slippage is Informational Only
- `slippage_usd` tracks the total adverse price difference between theoretical order trigger prices and actual executed fill prices (on entry and exit combined).
- **CRITICAL**: `slippage_usd` is strictly **informational and diagnostic**. It is **never** subtracted from `gross_pnl_usd`. Doing so would double-count slippage.

### C. Net PnL Identity
- Cash deductions from gross return consist strictly of exchange fees and historical perpetual funding rates:
  $$\text{net\_pnl\_usd} = \text{gross\_pnl\_usd} - \text{fees\_usd} - \text{funding\_usd}$$
- This identity must hold for every single exported trade (within floating-point rounding tolerance of $\le \$0.02$).

---

## 2. Column Definitions (17 Columns)

| # | Column Name | Type | Description |
|---|:---|:---|:---|
| 1 | `hypothesis` | string | Hypothesis identifier and version (e.g. `H1_v1.0.0`, `H2_v1.0.0`). |
| 2 | `symbol` | string | Perpetual futures ticker symbol (e.g. `BTCUSDT`, `SOLUSDT`). |
| 3 | `side` | string | Trade direction: `"long"` or `"short"`. |
| 4 | `entry_time` | string (ISO 8601) | UTC timestamp of entry order fill (e.g. `2023-02-13T03:20:00+00:00`). |
| 5 | `entry_price` | float (USD) | Executed entry fill price (incorporates entry slippage). |
| 6 | `exit_time` | string (ISO 8601) | UTC timestamp of exit order fill (e.g. `2023-02-13T17:15:00+00:00`). |
| 7 | `exit_price` | float (USD) | Executed exit fill price (incorporates exit slippage). |
| 8 | `exit_reason` | string | Cause of exit: `take_profit`, `stop_loss`, `sl_tp_same_bar`, `liquidation`, `manual_close`. |
| 9 | `qty` | float | Position size in base asset units (e.g. contracts/coins). |
| 10 | `stop_price` | float (USD) | Initial protective stop-loss price at order submission. |
| 11 | `target_price` | float (USD) | Initial take-profit limit price at order submission. |
| 12 | `initial_risk_usd` | float (USD) | Capital at risk ($1R$), computed as $|P_{\text{entry}} - P_{\text{stop}}| \times \text{qty}$. |
| 13 | `gross_pnl_usd` | float (USD) | Gross trade PnL computed directly from fill prices: $\Delta P \times \text{qty}$. |
| 14 | `fees_usd` | float (USD) | Total taker/maker exchange fees paid across entry and exit. |
| 15 | `slippage_usd` | float (USD) | Informational adverse execution cost vs reference quote price (already embedded in fill prices; never subtracted again). |
| 16 | `funding_usd` | float (USD) | Net funding paid/received over the holding period at actual Binance funding timestamps. |
| 17 | `net_pnl_usd` | float (USD) | Net realized profit/loss: $\text{gross\_pnl\_usd} - \text{fees\_usd} - \text{funding\_usd}$. |

---

## 3. Reconciliation Verification

All exported trades are tested by automated regression tests (`tests/test_research_framework.py::test_trade_csv_accounting_identity`) asserting:
```python
abs(net_pnl_usd - (gross_pnl_usd - fees_usd - funding_usd)) <= 0.02
```
